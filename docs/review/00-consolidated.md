# المراجعة الشاملة لـ HR-SYSTEM وخطة الإصلاح

| البند | القيمة |
|---|---|
| التاريخ | 2026-11-09 |
| الطريقة | Elephant-Goldfish Model: خمسة مراجعين بسياق جديد، كل منهم على مجال، دون معرفة بالمحادثة |
| النطاق | 21 صفحة، 14 تبويب إعدادات، `server.ts` (≈11,000 سطر، 206 مسارات)، `src/db/schema.ts`، المحركات في `src/lib` |
| القرار المرجعي | يُعتمد HR-SYSTEM منصةً للنظام المتكامل؛ OIL360 متوقف مؤقتاً؛ نظام المخصصات يندمج فيه كموديل رواتب |
| التقارير التفصيلية | `R1` ملف الموظف والهيكل · `R2` الترفيع والسلّم · `R3` الإجازات والعقوبات والتقييم · `R4` التدريب والتقارير والإعدادات · `R5` المنصة والأمان |
| مواصفة الرواتب | `docs/designs/payroll/requirements.md` (وثيقة متطلبات المخصصات والاستقطاعات 2.1) |

## 1. الخلاصة

**المحتوى والتصميم يستحقان الحفظ.** المراجعون الخمسة متفقون على أن الشاشات والتبويبات وحجم البيانات ونافذة الإعدادات (14 تبويباً) أساس جيد. يُضاف إليها مثلاً فلتر «اكتمال البيانات»، والأرشيف بلقطة JSON داخل معاملة، وتمديد الخدمة بأمر، وسلّم العناوين `next_title_id`، ومحرك الترفيع الاعتيادي ومسار الشهادة.

**المشكلة في الطبقة تحت الشاشات**، وتتلخص في خمسة أنماط متكررة:

| # | النمط | مثال |
|---|---|---|
| 1 | **ثغرات أمان** | أي نص base64 كان يُقبل رمز دخول؛ 78 مسار كتابة بلا فحص دور |
| 2 | **نجاح كاذب** | فشل قاعدة البيانات يُبتلع ويُكتب في الذاكرة ويُعاد 201 (179 موضعاً «fallback») |
| 3 | **قواعد في المتصفح** | نحو 25 مفتاح localStorage تحمل شروط المخصصات ونسبة التقاعد وسنوات الترفيع؛ متصفحان قد يحسبان راتبين مختلفين |
| 4 | **لا تاريخ ولا أمر** | الدرجة والمرحلة والعنوان والتشكيل تُكتب فوق القيمة السابقة؛ ستة مسارات كتابة للدرجة |
| 5 | **قيم قانونية خاطئة أو مختلقة** | التقاعد مرتين (20%)، الشهادة العليا مضاعفة، قطع الراتب 5 أشهر ثابتة، قيم افتراضية للتواريخ والدرجات الناقصة |

## 2. المرحلة A: الإصلاحات المنفذة في هذا الفرع (`fix/egm-review`)

انظر سجل الالتزامات (commits) للتفاصيل. مجموعات العمل:

| المجموعة | المحتوى |
|---|---|
| الأمان | JWT موقّع فقط؛ لا مفتاح سري ثابت في الإنتاج؛ `requireRole/requireAdmin/requireWriter`؛ كل مسارات الكتابة محمية (دور `employee` للاطلاع فقط) |
| لوحة التحكم | `control-app.bat <أمر>` لسطر الأوامر (status/start/stop/restart/build/backup/update/logs) مع رموز خروج؛ مفتاح JWT ≥ 32 حرفاً |
| محرك الرواتب (W1) | التقاعد مرة واحدة؛ فئة صريحة للبند بدل البحث في الاسم؛ قيم القانون الافتراضية؛ الشروط تفشل مغلقة؛ لا راتب بلا درجة؛ التقارير بنفس السلّم |
| الخادم (W2) | لا نجاح كاذب عند أخطاء القاعدة غير الاتصالية؛ حذف المسارات المكررة الميتة وفحص تكرار؛ GET لا يمسح أنواع العقوبات؛ إعادة الضبط في معاملة؛ فلاتر الحالة؛ إزالة البيانات الشخصية الحقيقية من البذور؛ مواءمة جداول الحضور والتقييم؛ ترحيل الإجازات 3 أيام/شهر بسقف 180؛ إيقاف إنشاء العناوين تلقائياً |
| قواعد الموارد البشرية (W3) | تاريخ الاستحقاق في الحركات؛ الخدمة المحتسبة مرة واحدة؛ نهاية المرحلة؛ «بيانات ناقصة» بدل القيم المختلقة؛ تمديد الاستحقاق بالإجازة الموقفة؛ الاستيراد بتواريخ ISO ومطابقة دقيقة؛ مفردات التدريب؛ العطل الرسمية وفق القانون 12/2024؛ إزالة السجلات المزيفة |

**ما لم يُنفَّذ في المرحلة A عمداً:** كل ما يغيّر بنية البيانات جذرياً أو يحتاج قراراً منك (القسم 4). إزالة طبقة التخزين الاحتياطي `data/local_storage.json` مؤجلة حتى يُقارن محتواها بقاعدة البيانات، لأنها قد تحوي بيانات غير موجودة فيها.

## 3. المرحلة B: تصاميم تُكتب وتُراجع بـ EGM قبل التنفيذ

كل بند هنا تصميم يُكتب في `docs/designs/<الاسم>/` بمهارة `/egm:egm-draft`، ويُراجع بـ `/egm:egm-review`، ثم يُنفذ. **الترتيب مقصود**: كل بند يعتمد على ما قبله.

| # | التصميم | المحتوى | يعتمد على |
|---|---|---|---|
| B1 | **ترحيلات قاعدة البيانات** | `drizzle-kit` بدل `ensureSchema` اليدوي؛ أنواع حقيقية (date/numeric/jsonb) بدل 373 عموداً نصياً؛ المفاتيح الأجنبية الاثنا عشر المفقودة؛ الفهارس | — |
| B2 | **إنهاء طبقة الذاكرة** | تقرير فروقات `local_storage.json` مقابل PostgreSQL؛ ترحيل الناقص؛ ثم حذف `inMemory*` و`saveLocalDb` وحدةً وحدة؛ سلوك واضح عند انقطاع القاعدة (ق-5) | B1، قرارك |
| B3 | **تقسيم `server.ts`** | اختبار لقطة المسارات أولاً، ثم Router لكل نطاق في `server/routes/`، وخدمات في `server/services/`، ومستودعات في `server/repositories/` (خطة R5 §6) | B1 |
| B4 | **سجل الموظف المؤرخ والأوامر** | جدول أوامر إدارية؛ سجل حقول بزمنين (النفاذ والتسجيل) للدرجة والمرحلة والعنوان والتشكيل والحالة ونوع الخدمة والمسؤولية؛ مسار كتابة واحد `careerMovements.apply()`؛ `employees` عرض مشتق | B1، B3 |
| B5 | **الهيكل التنظيمي والعناوين** | `org_units` بمفتاح أجنبي ورمز ثابت وتواريخ نفاذ؛ الموظف بـ `org_unit_id`؛ العناوين بمدى درجات وسند (قانون الملاك وتعديله 19/2024) وتواريخ | B4 |
| B6 | **القواعد من المتصفح إلى قاعدة البيانات** | نقل كل مفاتيح localStorage المالية والقانونية إلى جداول مؤرخة بأوامر؛ نسخة قراءة واحدة يستخدمها الخادم والواجهة | B1 |
| B7 | **الإجازات والانضباط** | دفتر حركات إجازات؛ لقطة نوع العقوبة JSONB؛ أحداث حالة إلحاقية؛ سحب اليد؛ مسار إعادة احتساب واحد | B4 |
| B8 | **موديل الرواتب على الخادم** | تنفيذ `docs/designs/payroll/requirements.md` داخل HR-SYSTEM: محرك البنود، الفترات واللقطات، المتغيرات المشتقة، الرجعي؛ الاحتساب على الخادم فقط؛ ترحيل بيانات نظام المخصصات | B4، B6، B7 |
| B9 | **التدقيق والاختبارات وCI** | `activity_logs` يكتبه الخادم بقيم قبل/بعد؛ اختبارات API (supertest) لكل دور؛ CI يشغّل lint وtypecheck وtest والترحيلات | B3 |

## 4. قرارات مطلوبة منك

مجمّعة من أسئلة المراجعين الخمسة (الأهم أولاً). لكل قرار المرحلة التي تنتظره.

| # | القرار | ينتظره |
|---|---|---|
| ق-1 | **`data/local_storage.json`**: هل نشغّل تقرير فروقات بينه وبين PostgreSQL على جهاز التشغيل، ثم نلغي طبقة الذاكرة؟ | B2 |
| ق-2 | **انقطاع قاعدة البيانات**: هل تقبل أن يتوقف الحفظ برسالة واضحة بدل «العمل دون اتصال» الذي يسبب تضارب البيانات؟ | B2 |
| ق-3 | **الأدوار**: هل يكفي (مدير / مستخدم / موظف)، أم نحتاج أدواراً مثل مسؤول رواتب، مسؤول تدريب، مدقق، مع تقييد حسب التشكيل؟ | B3، B9 |
| ق-4 | **تاريخ الموظفين الحاليين**: يبدأ السجل المؤرخ بسجل «تقديري» بتاريخ الترحيل، ثم تُدخل الأوامر التاريخية لاحقاً؟ | B4 |
| ق-5 | **سلّم الدرجات 8–10 و11–13**: ما المصدر الرسمي؟ نص المادة 4 يذكر 140,000 للدرجة 10 مرحلة 1، والنظام 170,000 | B4، B8 |
| ق-6 | **الخدمة المحتسبة**: تُمنح مرة واحدة عند صدور الأمر (مراحل/علاوات) أم تُطرح من الدورة الجارية فقط؟ | منفّذ مؤقتاً: الدورة التي يقع فيها تاريخ الأمر |
| ق-7 | **العناوين الوظيفية**: هل لديك جدول الملاك المعتمد للشركة وملحقا التعديل 19/2024 وتعليمات المالية 42042؟ | B5 |
| ق-8 | **الديانة والقومية**: ما الغرض الإداري الموثق، ومن يراهما؟ (صارتا اختياريتين بلا قيمة افتراضية) | B5 |
| ق-9 | **كتب الشكر**: سند مقدار القِدم والسقف السنوي، وهل يشمل العلاوة والترفيع معاً؟ | B7 |
| ق-10 | **تعدد العقوبات**: الأشد أم الجمع؟ وسند «الإلغاء بكتاب شكر»؟ | B7 |
| ق-11 | **ترحيل الإجازات**: يومياً (يوم عن كل 10 أيام خدمة فعلية) أم شهرياً بثلاثة أيام؟ | منفّذ مؤقتاً: 3 أيام/شهر |
| ق-12 | **العطل الرسمية**: نعتمد نص القانون 12/2024؟ ومن يحدد التواريخ الهجرية سنوياً؟ وهل عطل الأديان حسب ديانة الموظف؟ | B7 |
| ق-13 | **رصيد دورات الاختصاص**: يُولّد آلياً من التسجيل المجتاز أم بأمر منفصل؟ وما سند «أسبوعين لكل ترفيع»؟ | B6 |
| ق-14 | **الموظفون الفعالون**: هل يُحسب «متقاعد مع تمديد»؟ وما قائمة الحالات الرسمية؟ | B4 |
| ق-15 | **حذف الموظف**: يُمنع الحذف الفعلي ويُكتفى بحالة «منتهية خدمته» والأرشيف؟ | B4 |
| ق-16 | **قرارات وثيقة الرواتب**: القسم 19 من `docs/designs/payroll/requirements.md` (21 قراراً) | B8 |

## 5. طريقة العمل بعد هذا الفرع (Claude Code + EGM)

1. افتح المجلد في Claude Code وشغّل `/egm:egm-draft` لأول تصميم في القسم 3 (B1)، مع الإشارة إلى تقرير R5.
2. `/egm:egm-review docs/designs/<الاسم>/design_draft.md` ثم `/egm:egm-resolve`.
3. نفّذ على فرع مستقل، وشغّل `npm test` و`npm run build`، ثم اطلب مراجعة الفروقات.
4. `/egm:egm-drift-report` بعد كل مرحلة لمطابقة الوثائق مع الكود.
