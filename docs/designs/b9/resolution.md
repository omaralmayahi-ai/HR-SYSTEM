# B9 — الصلاحيات المرنة وسجل التدقيق وقاعدة السجل الذاتي وCI

التاريخ: 2026-11-11 · الترحيل `0018_b9_roles_audit` · القرار: ق-3 بالمتتبع (المدير ينشئ الحسابات والأدوار ويمنح الصلاحيات)

## ما نُفّذ
- **الأدوار المرنة:** جدول `roles`. كل دور له:
  - **أساس** (`admin` / `user` / `employee`) يحكم الشاشات والمسارات القديمة.
  - **صلاحيات دقيقة** تحكم وحدة الرواتب والإدارة: `payroll.view`، `payroll.enter`، `payroll.approve`، `payroll.settings`، `users.manage`، `audit.view`.
- **الأدوار الافتراضية:** تعيد السلوك السابق: `admin`، `user`، `hr`، `employee`.
- **مثال دور جديد:** «مسؤول رواتب» بأساس إدخال وصلاحية اعتماد الرواتب، بلا إدارة مستخدمين.
- **سريان الصلاحيات:**
  - الخادم يقرأ الدور **الحالي** للمستخدم من القاعدة، لا من رمز الدخول. تغيير دور مستخدم أو حذفه يسري فوراً، والمحذوف ما يدخل.
  - تعديل صلاحيات دور يسري فوراً بنفس الخادم، وخلال دقيقة بغيره.
  - دور غير معرّف = اطلاع بلا صلاحيات. يُكتب تنبيه بسجل الخادم بأسماء أصحابه.
- **منع رفع الصلاحية:**
  - ما يعدّل المستخدم دوره، ولا يحذفه، ولا يغيّر دوره هو.
  - من أساسه غير مدير ما يمنح أساس «مدير»، ولا يعدّل الأدوار النظامية.
  - ما يمنح أحد صلاحية ما يملكها، ولا يُسند دوراً فيه صلاحيات ما يملكها.
  - دور الاطلاع بلا صلاحيات.
  - دور `admin` محمي بمشغّل: يبقى بأساس مدير وبإدارة المستخدمين، وما يُحذف.
  - كل تعديل على الأدوار مسجّل بالتدقيق.
- **وحدة الرواتب:**
  - كل المسارات بالصلاحيات الدقيقة بدل «مدير/كاتب».
  - الاعتماد (عمليات، فترات، إصدار، إلغاء اعتماد) بـ `payroll.approve`.
  - الإسنادات والعائلة وجودة البيانات صارت لمن يملك `payroll.view` فقط. قبل هذا كانت ظاهرة لدور الاطلاع (تشديد مقصود).
- **سجل التدقيق (`request_audit`):**
  - إلحاقي بمشغّل: لا تعديل ولا حذف ولا تفريغ.
  - لكل عملية كتابة على الواجهة البرمجية: المستخدم، الدور، المسار، النتيجة، المدة، العنوان (`req.ip`)، والجسم.
  - يُحجب من الجسم كلمات المرور والرموز وأرقام الحسابات والهوية (حتى داخل نص JSON)، ويُقص الكبير.
  - الطلب المنقطع يُسجَّل بنتيجة 499.
  - شاشة «سجل التدقيق» بتصفية، بإدارة المستخدمين.
- **قاعدة السجل الذاتي (س15.3):**
  - ربط المستخدم بموظف (`users.employee_id`) من إدارة المستخدمين، مسجّل بالتدقيق.
  - المرتبط ما يعدّل ولا يعتمد على سجله:
    - تعديل الموظف، والحركات المؤرخة.
    - الإجازات (التعديل والاعتماد) والعقوبات والمؤهلات.
    - كل عمليات الرواتب بانتظار الاعتماد (إدخالاً واعتماداً)، ورفض المصرف.
  - طلب الإجازة لنفسه يبقى مسموحاً.
- **CI (`.github/workflows/ci.yml`):** على PostgreSQL 16 حقيقية:
  - فحص الأنواع بخط الأساس، واختبارات الوحدات، والبناء.
  - الترحيلات على قاعدة جديدة، وتطابق المخطط، واختبارات القاعدة كلها.
  - منع ملفات البيانات الحقيقية.
  - صلاحيات القراءة فقط.

## ملاحظات المراجعة المستقلة وحلها
| # | الملاحظة | الحل |
|---|---|---|
| H1 | صاحب «إدارة المستخدمين» يرفع دوره لمدير ويرفع الأدوار النظامية | `roleChangeProblem` + اختبارات + فحص حي (مرفوض بالحالات الثلاث) |
| H2 | مسارات المستخدمين القديمة تكتفي بأساس مدير | تحتاج أيضاً `users.manage`، وما يُسند دوراً بصلاحيات أوسع من المُسنِد |
| H3 | قاعدة السجل الذاتي ناقصة | أُضيفت للإجازات والعقوبات والمؤهلات ورفض المصرف. عمليات الرواتب مغطاة إدخالاً واعتماداً |
| M1 | تغيير الدور أو الحذف ما يسري حتى انتهاء الرمز (7 أيام) | سجل المستخدمين بالخادم: الدور الحالي من القاعدة، والمحذوف 401 + فحص حي |
| M2 | السجل يُظهر أرقام الحسابات والهوية، ودور اطلاع يكدر يملك `audit.view` | حجبها، ودور الاطلاع بلا أي صلاحية |
| M3 | عنوان IP يُزوَّر بترويسة | `req.ip` (يحترم trust proxy) |
| M4 | تغيّر سلوك بعض المسارات، ومعاينة الأثر الثقيلة صارت للاطلاع | موثّق أعلاه. المعاينة بـ `payroll.enter`. تنبيه بأسماء المستخدمين بأدوار غير معرّفة |
| M5 | التطبيق يتصل كمالك القاعدة فيكدر يعطّل المشغّلات | **توصية تشغيل:** مستخدم قاعدة للتطبيق غير مالك، بـ INSERT/SELECT فقط على جداول التدقيق. خارج الكود |
| L1 | الطلب المنقطع والـ JSON التالف ما يُسجَّلان | المنقطع يُسجَّل (499). التالف يرفضه المحلل قبل الوصول، **باقٍ** |
| L2 | الحجب يطابق `mapping` ويفوّت JSON داخل نص | مطابقة بالحدود، وفك JSON داخل النص + اختبار |
| L3 | سباق حذف الدور | **باقٍ:** آمن (يُعامل اطلاعاً)، ومفتاح أجنبي لاحقاً |
| L4 | كلفة شاشة السجل مع الحجم | **باقٍ:** فهرس الزمن والمستخدم. سياسة الاحتفاظ قرار تشغيلي |
| L5 | الواجهة | قائمة الأدوار الاحتياطية تشمل الأربعة والدور الحالي. شاشة المستخدمين لأساس مدير (موثّق) |
| L6 | CI بلا صلاحيات محددة، واختبار يترك صفاً دائماً | `permissions: contents: read`، والاختبار داخل معاملة تُلغى |
| L7 | اختبارات ناقصة | قواعد الأدوار، والحجب، والصلاحيات بالمسارات، وحماية دور المدير، والسجل الإلحاقي |
